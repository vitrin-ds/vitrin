# Vitrin

Vitrin is an e-commerce system for agencies and freelancers who build client stores: the parts in
this repository are free, and ready-made stores built from them are sold at
[vitrin.design](https://vitrin.design). Everything here is MIT-licensed and runs on Next.js.

- **Demo store:** <https://demo.vitrin.design>
- **Components, blocks and pricing:** <https://vitrin.design>
- **Storybook** (every component, its variants and states): <https://vitrin.design/storybook/>
- **Install guide:** [cli/README.md](cli/README.md)

## Install

In a Next.js project (App Router) with Tailwind CSS 4:

```bash
npx @vitrin-ds/cli add mini-cart
```

The code is copied into your project, so you own it and can change it. The first run also adds
Vitrin's tokens and theme. `npx @vitrin-ds/cli list` shows every item.

## The data contract

A block never calls a backend itself. It reads and changes data through `CommerceAdapter`
(`src/lib/commerce/commerce-adapter.ts`), which has six parts: `catalog`, `cart`, `checkout`,
`customer`, `orders` and `addresses`. A block takes only the parts it uses.

Every connected block installs with an in-memory adapter and sample data, so it works the moment it
is installed: open the page, click, and it acts. The blocks that touch the cart also install the
Shopify cart adapter.

| Block                      | Installs with                                       | Works as installed                                                                                                                    |
| -------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `product-list-connected`   | `createMockCartAdapter`, `createShopifyCartAdapter` | Shows the products you pass; Add to cart adds to the in-memory cart                                                                   |
| `product-detail-connected` | `createMockCartAdapter`, `createShopifyCartAdapter` | Shows the product you pass; Add to Cart and Buy Now add to the in-memory cart                                                         |
| `cart-connected`           | `createMockCartAdapter`, `createShopifyCartAdapter` | Changes quantities, removes lines, takes coupon codes you give the mock                                                               |
| `mini-cart-connected`      | `createMockCartAdapter`, `createShopifyCartAdapter` | Reads and changes the in-memory cart                                                                                                  |
| `account-orders-connected` | `createMockOrderAdapter`                            | Lists two sample orders                                                                                                               |
| `account-addresses`        | `createMockAddressBookAdapter`                      | Adds, edits, deletes addresses and sets defaults, starting from one sample address                                                    |
| `checkout`                 | `createMockCheckoutAdapter`                         | Guest checkout with two delivery options; places an order. Card `4000000000000002` is declined, `4000000000003220` asks for 3D Secure |

The catalogue is yours: product blocks show the products you pass them, from wherever you read
them.

### From the mock to Shopify

One line: swap the cart adapter.

```ts
// Before: an in-memory cart
const cart = createMockCartAdapter();
// After: the cart of your Shopify store
const cart = createShopifyCartAdapter({ endpoint, storefrontToken, cartId });
```

The blocks don't change. `endpoint` is your shop's Storefront API address, `storefrontToken` a
Storefront API token, and `cartId` the id of a cart created with the Storefront API (`cartCreate`).
See [cli/README.md](cli/README.md).

### Writing your own adapter

Fill the same interface for your backend; the blocks don't change. One rule for the cart:
`addLine(variantId, quantity?, { preview })` receives what the block shows about the product
(name, picture, price). The preview is for display only. An adapter with its own catalogue takes
price, stock and variant from its own source and never trusts the preview's price; the Shopify
adapter ignores the preview entirely. Only an adapter without a catalogue, like the in-memory
mock, builds the line from it.

## What is missing today

- The Shopify adapter covers the cart only (lines, quantities, discount codes). There is no
  Shopify catalogue adapter yet, and checkout, customer, orders and addresses on Shopify are not
  written: on Shopify, checkout happens on Shopify's own checkout page.
- Next.js only (App Router, React 19, Tailwind CSS 4). No other framework.
- Product photography and brand logos are not in this repository. Stories use neutral sample
  art, and payment, social and flag marks show a text or placeholder until you add your own files.
